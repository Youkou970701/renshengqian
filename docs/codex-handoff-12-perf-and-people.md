## 第一段：卡顿（做完先停）

原因和修法见 `design-v3-gap.md` 第一节，要点：
1. `src/ui/App.jsx` 第 167 行每次状态变化都整份 `JSON.stringify(state)` 写 localStorage。改成**只在推进一年 / 完成选择 / 页面隐藏（visibilitychange）/ pagehide 时存**；计时（`pacingElapsedMs`）和动画帧不触发存档。
2. 同秒出生的 4 个人**只存编号和已推进的年龄**，读档时用纯引擎重算（确定性保证结果一致，加测试：存档→读档后 4 个人的状态与不存档直接推进完全一致）。
3. 人生纪录**只渲染最近 30 条**，其余「查看更早」展开；纪录项 memo。
4. 首屏**按需加载**：reference.json、图鉴频率、称号库、统计出处页、分享卡生成用动态 import。
5. **验收门槛**（写进 `scripts/check-perf-12.mjs`，用 Playwright / Chrome 375px + 4× CPU 降速）：
   - 推进 60 年（自动选择），主线程长任务（>50ms）≤ 3 次；
   - 首屏 JS gzip ≤ 150KB；
   - 每推进一年 localStorage 写入 ≤ 2 次；
   - 存档大小在 80 岁时 ≤ 120KB；
   - 旧存档（含 peers 全量）能迁移，不丢进度。
6. 原 25 项校准、全部测试保持通过（这段纯 UI，快照应逐字不变）。

## 第二段：让人生「有人」

### A. 家人和朋友是活的
- 主界面加「家人与生活」：配偶、每个孩子、父母、兄弟姐妹、1–2 个好朋友——**名字、年龄、职业、关系亲疏（亲近 / 一般 / 疏远）**；过世的显示几岁离开。
- 亲疏会因选择和事件变化（陪伴、借钱、照顾、吵架、长期分居、留守……），并影响后面的卡（疏远的孩子少来看你、亲近的兄弟肯借钱、关系好的配偶危机少）。
- 日常事件优先写人，**用名字**：孩子的奖状、配偶生病、父母忌日、朋友结婚、孙辈第一次叫你……
- **门槛**：25 岁以后的日常事件里，提到具名家人或朋友的 ≥ 40%；每局至少一次亲疏变化且日志写出原因。

### B. 身边人的两难 + 后续
- 新卡类「身边的人」：邻居、同事、陌生人、亲戚、老同学、学生、病友……至少 **20 张**，覆盖童年到晚年。
  例（自己写，别抄原作）：同事被冤枉你知情、路边有老人摔倒、亲戚借钱做担保、班上有人被孤立、老板让你在单据上签字、朋友找你借身份证办卡、楼上装修吵了半年、外卖骑手被投诉求你作证……
- 每张至少 3 个后果不同的选项，并用已有的**伏笔机制**在 1–5 年后回来一条后续（「那个同事后来当了领导，还记得你」「被你扶起来的老人家属送来了锦旗」「担保的钱最后你替他还了」）。
- 涉及违法的（借身份证办卡、签假单据）写清后果，不写方法，沿用红线。
- 和处境变体一样按城乡 / 家境 / 职业出不同版本（复用 `variants.js` 的尺子）。
- **门槛**：每局「身边的人」卡中位数 ≥ 2；其中 ≥ 60% 在后面真的出现了后续。

### C. 去掉账房腔，钱有故事
- 把这些说法从玩家文本里彻底去掉，加进生硬表达清单（测试扫描 2000 局实际日志 = 0）：
  「系数」「按完整十二个月」「恢复了在岗工作」「重新开始领取工资」「收支平常」「年景周期」「求职空档」「在岗月份」。
- 年度经营结果、行业周期、失业复工改写成**具体的事**，每种结果至少 6 种说法，**同一句话不能连续两年出现**（测试）：
  「街口又开了一家同样的店，生意被分走一半」「厂里接了个大单，连加了三个月班，年底多发了一个月工资」「店里的老顾客搬走了好几户」……
- 钱面板：「过去一年净资产变化」按来源分解（工资存下、经营盈亏、房贷利息、房价涨跌、给家里的钱、意外支出……），加一行「收入在全省第 X%、全国第 Y%」。
- 事件里的钱要跟着故事出现：「暴雨淹了店里的货（−6000 元）」。
